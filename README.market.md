## 能力速览（人话版）

### 它怎么保证"交不出半成品"（门禁）
- 拆任务时静态校验结构是否合法（有执行必有验收等）；
- 派活前检查上游产物齐不齐——缺了**拒派**；
- 结算前检查产物落没落盘——缺了**拒收**；
- 批次完结前检查验收做没做完——没做完**不许关账**。

### 它怎么保证"崩了不重来"（恢复）
- 每步成果 checkpoint 进 git，可查可救；
- 进程崩了，在跑成员自动落回待命池，重派新 worker 从 checkpoint 续；
- 失败 lane 是终态，重做=开新批次——语义干净，绝不"接着跑出个脏状态"。

### 它怎么保证"查得到账"（审计）
- 状态文件唯一事实源 + 事件日志导出（按 lane/类型/时间过滤）；
- 20 个治理工具：批次规划 / 门禁 / 资产归位 / 锁 / 成员状态 / mailbox 通信 / 心跳 / worktree 隔离 / 日志。

### 它怎么保证"不越界"（角色）
- 3 层 8 角色：任务层（Coordinator/Manager/Designer）+ 执行层（Coder/Tester/Reviewer）+ 审计层（Supervisor/Doc-Manager）；
- 派发时自动注入角色**权限边界**——Tester 不改码、Reviewer 只读，防越界不靠自觉。

---

## 边界（诚实说明）

- **单机多子 Agent 治理**：在同一 dsh 进程内治理一批 worker——不做分布式集群同步、无成本控制、无模型分层路由；
- 续跑提供 checkpoint 保全与恢复审计，失败 lane 仍终态、重做仍开新批次（语义优先于"续命"）。
