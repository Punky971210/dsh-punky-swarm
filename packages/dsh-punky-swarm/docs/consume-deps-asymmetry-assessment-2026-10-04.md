## 0. 结论摘要（三句）

1. **缺口现象成立，但缺口文档的两条建议需要两处订正**：§5.A 的「对称性必核」若**一刀切**，会把引擎语义里**有意合法**的写法判成错误（证据见 §2）；§5.B 的 B-2 风险（「会拒掉历史写法」）**被高估**——引擎自己的合规夹具本来就是对齐的。
2. **补法应分域**：`audit lane` 的 `consume` 来源要求 `deps` 对齐（痛点全在这里）；`exec` 消费 `plan` 产物则**维持「在场性」语义**，不强制交接边。
3. **编制推荐**：小口径（指引条文 + B-1 观察事件，≈2–3M）→ **A 档 Leader 直做**；大口径（+ B-2 拒态 + 全量验证 + 宿主冒烟，≈8–10M）→ **C 档两 lane（exec / audit 两波）**。**D 档在本任务上无增益**（无长跑、无跨会话续跑、无成员复用需求）。

## 2. 关键设计分歧：`consume` 来源 ⊆ `deps` 该不该一刀切

### 2.1 为什么不能一刀切（两条硬理由）

**理由一 · 引擎语义**：`consume` 与 `deps` 语义**本不必等价**（§1 C1）。`plan-mutate.js` 的错误消息是引擎**自己**给出的分流指引：「在场」走 `consume`、「等交接」走 `deps`。一刀切 = 取消「只要在场」这一合法态。

**理由二 · 运行期代价**：`deps` 是**交接边**，而「入边 `submitted` 是下游开工硬前提」。若强制「所有 `consume` 来源都要有边」，则**每个 exec lane 都必须等自己的 plan lane 先 `handoff_submit`** ⇒ 运行期交接数量从「链式若干条」涨到「**≈ lane 数**」，治理开销随批规模线性上升。

### 2.2 分域处置（本报告建议的口径）

| 域 | 消费关系 | 建议 | 理由 |
|---|---|---|---|
| **A** | **audit lane** 的 `consume` 来源 | **要求 `deps` 对齐**（观察 → 拒态） | audit 的取件语义本就是「从谁那儿、拿到什么、承诺什么断言」——`handoff.assertions` 正是为验收设计的；**两个实例的痛点全在 audit lane（a01）** |
| **B** | **exec lane** 消费 `plan` 产物 | **维持现状**（在场性即可，不强制边） | 判据源的在场面已由 entry 门 `GATE_ENTRY_MISSING` + `planProduces` 静态校验覆盖；强制边只增开销、不增判据强度 |
| **C** | **同层 / 同链** lane 间产物依赖 | **要求 `deps` 对齐** | 这类消费**本就是**「等上游产出再干」，交接边是其真实语义 |

> 该口径把 B-2 的冲击面从「所有层」收窄到「audit 面 + 同层链」，与 C2 的夹具证据一致。

## 4. C 档 / D 档施工编制设计

### 4.1 先过预算面（§14：单 lane `W` 必须落 4M–10M，本机 `C≈232K/轮`）

| 工作包 | 预估轮次 | 预估 `W` |
|---|---|---|
| W1 指引线 | 6–8 | ≈1.4–1.9M |
| W2 引擎观察面 | 12–15 | ≈2.8–3.5M |
| W3 拒态 | 8–10 | ≈1.9–2.3M |
| W4 验证线 | 8–12 | ≈1.9–2.8M |
| **合计（大口径）** | — | **≈8–10.5M** |

⇒ **结论**：全量拆成 3–4 条 lane 会**逐条跌破 4M 下界**（§14 禁止）；正确切法是**压成 2 条**（exec 承担 W1–W3 ＋ 子集自证 ≈7–9M ✓；audit 独立复验 W4 ≈3–4M，贴近下界）。
⇒ 而**只做 W1+W2**（小口径）总量 ≈2–3M，**低于 4M ⇒ 不应拆、不应建批 ⇒ A 档 Leader 直做**。

### 4.2 两档编制对比

| 维度 | **C 档**（`wave_plan` 集群批） | **D 档**（team 通道 durable 席位） |
|---|---|---|
| 派发方式 | 引擎自派 subagent；黑板写 `owner` + `member.dispatch{workerSessionId, lane}` | Leader `spawn_teammate` 拉起；黑板写 **`roster`** 成员名，拉起后通知成员 |
| 交接 | `handoff_submit` + `lanes[].deps`（引擎自动派发） | **事件队列**（`lane.handoff` + `log_export`；`send_message` 为已开放汇报通道） |
| 席位 | 一次性 worker（TTL 句柄） | **durable 席位**（可跨波次复用、in-flight 落 `idle` 可重派） |
| 适用判据 | ≥2 条可并行线 **或** 多依赖需 DAG 分层 | C 档判据 **＋** 长跑 / 跨会话续跑 / 成员复用 |
| 本任务适配 | ✅ 大口径下 exec→audit 天然两波（DAG 分层） | ⚠️ **无长跑、无跨会话、无复用需求** ⇒ 差异化优势**零对价**，只多一层手工 roster 开销 |
| 启动开销 | 低（写黑板即派） | 中（逐个拉起 + 写黑板通知） |
| 收口 | 逐 lane 结算 + `batch_phase(complete)`；**audit lane 必须显式结算** | **同左**（引擎层仍以 C 写入 ⇒ D ≡ C + team 通道约定） |

### 8.1 两条偏离的落地推演

- **Q-4=甲（同层链纳入）**：拒态面从「仅 audit」扩到「audit ∪ 同层」。→ spec 需给出 **L.layer × T.layer 判定表**，并保留「上游 plan 层不要求边」这一域 B 例外。
