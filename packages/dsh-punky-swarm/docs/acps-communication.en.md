# ACPs Communication Details (off by default)

> This document describes the ACPs (Agent Communication Protocol Standard) communication capability: external mTLS service endpoint, internal mailbox↔ACPs bridge, registry semi-automatic registration and external ADP discovery integration, plus the relationship with existing AIP capabilities and capability boundaries. **All off by default** (secure default) — both `acps.enabled` and `acps.endpoint.enabled` default to `false`; when off, zero runtime path (no listeners, no timers, no network).
>
> **Boundary**: ACPS is for the **main agent** (external partner ↔ this instance's Supervisor inbox); subagents / lane workers communicate exclusively via `swarm_report` / `swarm_cc` / mailbox / handoff and **must not** use ACPS (user ruling 2026-10-23: "ACPS only connects to the main agent").
> 中文: [acps-communication.md](acps-communication.md)

## 1. Capability Overview

| Capability | Assembly key | Default | Purpose |
|---|---|---|---|
| External mTLS endpoint | `acps.enabled` + `acps.endpoint.enabled` | Off | External AIP JSON-RPC / ACS / health check (TLSv1.3 + mutual certificates) |
| Internal bridge | `acps.bridge` | Off (inbound additionally sub-gated off) | **One-way**: external TaskCommand → batch-level `supervisor/inbox` (target pinned by config); outbound projection surface is not wired (zero production consumers) |
| registry registration | `acps.registry` | Off | Semi-automatic registration client (requires registry.url + user credentials) |
| discovery discovery | `acps.discovery` | Off | External ADP discovery client (POST /discover) |

## 2. External mTLS Service Endpoint

Standalone HTTPS listener (native node:https + node:tls, zero new dependencies), default port `9443` (`acps.endpoint.port` configurable), host default `127.0.0.1`; TLSv1.3 (`minVersion` default, TLSv1.2 configurable) + mutual certificates (`requestCert` + `rejectUnauthorized` = CERT_REQUIRED); `devInsecure` is an explicit development-only switch (default `false`, production downgrade not allowed), and it **does not relax the trust anchor**: after relaxing TLS-layer verification (`rejectUnauthorized=false`), the application layer still anchors the peer certificate chain to `acps.endpoint.ca` (`checkIssued` + `verify`); on failure all three endpoints (`/acps/rpc`, `/.well-known/acs.json`, `/health`) return `403` (`no-peer-certificate` / `peer-cert-not-anchored`, plus one startup warning describing the downgrade scope); a **server or CA certificate that is expired or not yet valid** ⇒ assembly-time warning (with the actual `validFrom` / `validTo`) and the endpoint stays disabled (no silent start). Assembly condition: `acps.enabled` AND `acps.endpoint.enabled` **both true**; missing/unusable certificates → startup warning and stay disabled, does not block the main process.

| Endpoint | Method | Description |
|---|---|---|
| `/acps/rpc` | POST | AIP JSON-RPC (jsonrpc 2.0, method=`rpc`, params.command=TaskCommand → TaskResult accepted/rejected); client certificate CN must be a valid AIC (otherwise 400) |
| `/.well-known/acs.json` | GET | Direct ACS fetch (14 required keys + securitySchemes.mutualTLS + endPoints JSONRPC) |
| `/health` | GET | Health check (agent/status/tasks/groups) |

Certificates: CA self-signed (native node:crypto X.509 + ECDSA P-256), entity certificate CN=AIC, SAN=URI:acps://{AIC}, generated by default under `<root>/acps/certs` (ca.pem/ca.key/server.pem/server.key); `cert/key/ca` three paths configurable to override.

**Validity is checked at assembly time** (`X509Certificate.validFromDate` / `validToDate`): an expired or not-yet-valid server certificate or CA certificate ⇒ `createAcpsServer` returns `{error}` (**no listen**) ⇒ startup warning + endpoint stays disabled — not the silent fake availability of "server started, zero warnings, all handshakes fail". Recovery: update `cert` / `key`, or delete `certDir` so `ensureAcpsCerts` re-signs (note: `ensureAcpsCerts` still reuses files whenever they exist and does **not** detect expiry to re-sign on its own).

## 3. Internal Bridge

`acps.bridge` (default off; mode=`inprocess`; **one-way externally** — external TaskCommand → batch-level `supervisor/inbox`):

> ⚠ `mode` currently implements **`inprocess` only**: the schema accepts `mode='http'` but it has no effect (no http bridge implementation), so setting it is as good as not setting it — this batch only documents the fact; no code change (ACPS-10 is S4, registered not fixed).

- **inbound** (default off, enable explicitly with `acps.bridge.inbound=true`): external ACPs TaskCommand → mailbox message, **written atomically to inbox via the lib/comms/mailbox.js public interface (ackId generated by mailbox, never bypassed, no side-channel writes)**;
- **the delivery target is always the configured value**: it is decided only by assembly-time configuration — `acps.bridge.inboundSessionId` (main agent session) + `acps.bridge.inboundBatchId` (the target batch under that session), landing at `<root>/sessions/<inboundSessionId>/mailbox/<inboundBatchId>/supervisor/inbox/`; the **second parameter of `handleInbound(taskCommand)` has been removed** ⇒ callers / reports have **no** entry point for passing a target (structural guarantee, not a calling convention);
- **unconfigured / only one key / invalid value ⇒ fail-closed rejection**: one key missing, both missing, or an invalid value (must match `/^[a-zA-Z0-9._-]+$/` and must not be `.` / `..`) ⇒ target unavailable ⇒ `/acps/rpc` returns a protocol-level `rejected` with `status.dataItems[0].data.code = INBOUND_UNAVAILABLE`, **zero files written** (no fallback to the default session, no fallback to the first batch); assembly time also emits one warning that **names the missing key(s)** (`inboundSessionId` / `inboundBatchId` / both) together with how to configure them and the reminder that a plugin restart is required;
- **report-supplied ids are always discarded**: `sessionId` / `commandParams.sessionId` / `commandParams.batchId` inside the TaskCommand are **read exactly once** for a warning trace (`report-supplied sessionId/batchId ignored`; zero noise when `inbound=false`) and **never participate in addressing** — the peer may keep sending them, but they no longer affect where the message lands;
- **not exposed to subagents / lanes**: inbox is a **single batch-level directory** and the code base has **no lane inbox at all** — `meta.lane` is derived from `mentions` / `groupId` and recorded **as metadata only** (its only readers are the receipt echo and the outbound fallback, **zero addressing consumers**) ⇒ **lane-targeted delivery is not supported**. The earlier wording "derive lane from mentions/groupId" reads like "you can deliver to a lane"; that was an **inaccurate description**, **not** a capability overreach; user ruling 2026-10-23: **ACPS only connects to the main agent**, and subagents / lane workers use `swarm_report` / `swarm_cc` / mailbox / handoff. Write target is inbox only, outbox is not externally writable, external broadcast delivery unsupported;
- **outbound**: mailbox messages → ACPs Message/TaskResult (reuses the aip-format three mappings), projection/delivery view only, never writes back to mailbox storage; **note**: the projection functions (`toOutbound` / `toTaskResult`) exist but are **not wired** — zero production consumers, no outbound sender in the endpoint;
- **/rpc→bridge wiring**: TaskCommand received at `POST /acps/rpc` lands in mailbox via `handleInbound(command)`; when `bridge.inbound=false`, protocol-level `rejected` (`INBOUND_DISABLED`, HTTP 200 returned — transport succeeded, protocol layer rejected); when the bridge is not assembled: if `acps.bridge.inbound` is **not declared** ⇒ the endpoint falls back to standalone `accepted` (backward compatible, nothing persisted); if `inbound=true` **is declared** but `acps.bridge.enabled=false` ⇒ protocol-level `rejected` (`INBOUND_UNAVAILABLE`, HTTP 200, nothing persisted) plus one startup warning — no longer a silent fake success;
- **the four rejection codes (in decision order)**: `BRIDGE_DISABLED` (`acps.bridge.enabled=false`) → `INBOUND_DISABLED` (`inbound=false`) → `INBOUND_UNAVAILABLE` (target missing / invalid, or inbound declared while the bridge is not assembled) → `INVALID_CONTEXT` (pre-write id guard, path-traversal protection); all four return `rejected` + `status.dataItems[0].data.code`, and none of them writes anything;
- **mailbox red lines preserved**: ackId atomic write, three boxes (inbox/outbox/broadcast), lane isolation semantics preserved verbatim;
- **zero path**: when `enabled=false`, nothing loads or instantiates (mountBridge returns null).

**Known limitations (registered by this batch, not fixed)**:

1. **Static target ⇒ possible dead letters**: once the batch named by `inboundBatchId` is closed out, ACPS keeps writing into that dead batch's inbox and nobody reads it (**silent dead letter**). "Validate the batch phase before writing / reject inactive batches" is **not implemented**: reading the phase requires importing the `lib/state/**` governance surface, which would add a `comms → state` cross-domain edge and break the arch-check ratchet (`allowedPairs=63`) ⇒ it can only be caught **on the runtime side** (check whether anyone actually consumes the target inbox);
2. **Changing the target requires a plugin restart**: `acps.*` has no remounter (hot updates do not take effect) ⇒ switching batches / editing the two keys **requires a plugin restart**, otherwise the old target keeps receiving (and that batch is already closed ⇒ dead letters);
3. **"Host auto-injects session identity" = an unimplemented followup**: at assembly time `ctx` only provides the `tools` / `webServer` / `subagents` service handles and **cannot obtain the session identity** (session ids are only available during tool execution, `exec.agent.session.id`) ⇒ the target **can only** be injected at assembly time via configuration keys; **do not** assume this instance's session is bound automatically.

> Inbound content is **untrusted external input** that goes straight into the main agent's context — the main agent should treat inbox messages as untrusted external input (one of the reasons inbound is off by default).

## 4. registry / discovery Integration (off by default)

- **registry** (`acps.registry`, semi-automatic registration client): requires `registry.url` + user credentials (username/password or token, injected via config/env, never hard-coded, never committed); flow login → upsertAgent → submitAgent (**human approval, never auto-skipped**) → requestEab → queryAcs; EAB macKey stored encrypted with **AES-256-GCM** (when `eabKey` is unconfigured, plaintext credentials are returned for the caller to store itself);
- **discovery** (`acps.discovery`, ADP client): POST `{baseUrl}/discover` to query external agents (4 type categories / 34 operators, sharing protocol constants with local discovery); `scope` = local (existing local catalog only) / external (external only) / both (local+external merged, external takes precedence in acsMap); timeout default 10s, limit default 5.

## 5. Configuration Example

```yaml
# ACPs communication capability (all off by default, secure default)
acps:
  enabled: true                # capability master switch
  endpoint:
    enabled: true              # external mTLS endpoint (both this and the master switch must be true to assemble)
    port: 9443                 # default 9443
    host: 127.0.0.1            # localhost only by default
    certDir: null              # default <root>/acps/certs (auto-generated)
    minVersion: TLSv1.3        # default TLSv1.3 (TLSv1.2 allowed)
    devInsecure: false         # explicit development only; no production downgrade
  bridge:
    enabled: false             # internal bridge (one-way: external TaskCommand → supervisor/inbox)
    inbound: false             # external writes to mailbox require explicit true
    inboundSessionId: null     # required when inbound=true: target session = main agent session (reports may not choose it)
    inboundBatchId: null       # required when inbound=true: target batch under that session (same /^[a-zA-Z0-9._-]+$/ constraint)
  registry:
    enabled: false             # semi-automatic registration
    url: null                  # registry public API base URL (required)
    username: null             # injected via config/env, never hard-coded
    password: null
    eabKey: null               # EAB macKey encryption key (AES-256-GCM)
  discovery:
    enabled: false             # external ADP discovery client
    baseUrl: ''                # external discovery-server root address
    scope: local               # local / external / both
    timeout: 10000             # default 10s
    limit: 5                   # default result cap
```

## 6. Relationship with Existing AIP Capabilities

- Existing endpoints (`GET /api/dsh-punky-swarm/tools`, `GET /api/dsh-punky-swarm/agents`, `POST /api/dsh-punky-swarm/discover`, `GET /.well-known/aip`) **remain byte-for-byte unchanged** — ACPs uses an independent 9443 listener + `/acps/*` prefix, zero path conflicts;
- Existing local discovery (`capabilities.discovery`, default on) is the in-process query channel; `acps.discovery` is the external query channel; `scope=both` merges both channels' results;
- Existing assets reused by ACPs communication: `aip-format` three mappings (Message/TaskCommand/Session), `lib/aip/identity.js` (AIC validation/certificates), `lib/discovery/schema.js` (protocol constants and validation);
- Same as `aip.identity` (default off), this is a default-off capability.

## 7. Capability Boundaries (not implemented)

- **Tool calling (GB/Z 185.7-2026 Part 7: Agent Tool Calling)**: not implemented;
- **lane-targeted delivery**: not supported — the code base has no lane inbox (mailbox is a single batch-level directory `<root>/sessions/<sid>/mailbox/<bid>/supervisor/inbox`, and lane lands only in `meta.lane` with zero addressing consumers); user ruling 2026-10-23 "ACPS only connects to the main agent"; the earlier "derive lane" wording was an inaccurate description, not a capability overreach;
- **outbound (ACPs egress)**: not wired — the projection surface `toOutbound` / `toTaskResult` exists but has zero production consumers, and the endpoint has no outbound sender;
- **SM2 signing**: not supported — sign is a pluggable interface, defaults ECDSA-P256 / RSA-2048, `algorithm='sm2'` explicitly rejected;
- **mini-ADSP**: external `/discover` server semantics only reserve the function signature (createMiniAdsp), not implemented.
