# V-22 类判据（逐项可回滚）的核法 —— 不依赖物理 commit

- 适用仓：`packages/dsh-punky-swarm`
- 来源：批次 `punky-core-ports-20261114` 的 `plan/port-spec.md` V-22（收口复验时判为「实施期物理不可达」）
- 快照：HEAD `d259385`（文中 `file:line` 以此为锚，漂移时按符号名重定位）
- 性质：**判据规范**。只声明「怎么核」，不含实现、不规定任何批的交付形态。

---

## 1. 判据本意

「逐项可回滚」要证的是**各项改动彼此独立**（一项缺席时其余项仍按原样工作），不是「git 历史长什么样」。
独立回滚是**代码面性质**。把判据写成「历史里有 7 个 commit」，是拿提交粒度去代理依赖粒度 —— 两者不等价。

## 2. 正确核法：文件面 / hunk 面（默认口径，任何批都可执行）

| # | 核什么 | 怎么核 | 判红的样子 |
|---|---|---|---|
| **C-1** | **异文件** | 逐项列出写域文件清单，两两求交集；无关项之间交集必须为空 | 两项同时改同一文件，且各自 hunk 交错、无法单独摘除 |
| **C-2** | **异 hunk** | 同文件不可避免时，各 hunk 的 `@@` 区块互不重叠、不共享上下文行，可单独摘除 | 摘掉一项的 hunk 必须连带摘另一项的行 |
| **C-3** | **共享模块未被无关端口改动** | `lib/core-ports.js` 等共享面只允许「本项对应的注册/读取行」变动；无关端口的注册逻辑不得随本项变化 | 某批次顺带重排了共享模块的既有结构 |
| **C-4** | **端口缺席时回落同实现** | 逐项做一次性探针：在**临时副本**里删掉该端口键（不写仓库），相关测试仍通过、行为回到原始实现 | 删掉某端口键后，另一项随之报错或行为改变 |

每项至少留 1 条 C-4 探针读数（命令 + 期望结果）；C-1…C-4 全绿 ⇒ 「逐项可回滚」成立。

## 3. 为什么不能靠「7 个物理 commit」

1. **实施期不存在**：批次纪律常是「lane 不 commit、由 Leader 批末统一提交」（或整批一个提交）⇒
   物理 commit 数在实施期根本没有，判据**物理不可达**，于是每批都要为它重新争一次口径。
2. **成本高于收益**：人为把一次自洽的改动切成 7 个 commit 会**重写历史**，历史失真、bisect 与还原成本上升；
   换来的只是满足一条本可由 C-1…C-4 直接达成的判据。
3. **达标也不等于独立**：commit 数够了不证明独立性 —— 一个 commit 里可以同时含两项改动（少拆、或拆错边界）。
   commit 是提交粒度，不是依赖粒度。
4. 结论：以 **C-1…C-4 为主判据**；commit 面最多作旁证，不单独充当独立性证明。

## 4. 若某批确实物理拆了 commit

两种核法**都要过**：

- C-1…C-4 全绿（主判据，不因拆了 commit 而免除）；
- V-22 原文的历史面全绿：`port(X-n)` commit 数达标、逐项 revert 后 `npm test` 退出码 `== 0`、
  V-20 等价读数不变、需要连带 revert 的项数 `== 0`。

任一不过 ⇒ 该项实现越界。**不得**在两者之间二选一。

## 5. 两条禁令

- 不得用「本批未拆 commit」推导「独立性未验证」⇒ 这是**漏证**（C-1…C-4 未做）。
- 不得用「commit 已拆 / revert 成功」代替 C-1…C-4 ⇒ 这是**假证**（共享模块的耦合不会被 revert 暴露）。
