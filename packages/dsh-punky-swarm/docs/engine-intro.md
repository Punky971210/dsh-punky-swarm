# 蟛蜞工程引擎 · 介绍

> 本文件是引擎的**对外介绍与设计对照基线**：把四条原始设计理念与当前实现逐条对齐，供使用者、二次开发者与维护者共同引用。
> 术语：**引擎** = 本插件（dsh-punky-swarm）；**团队** = 可拔插的装配资产（`presets/<team>/team-asset.yml`）；**批次 / lane** = 一次治理执行的容器与执行单元。

## 一、定位

- 这是**工程/技术型引擎**：与主打"简单任务提效"的 Harness 叙事有根本差异——它的全部机制都服务于**有验收标准的专业交付**；
- 它是**专业技术团队 Agent 化的地基**，不是岗位提效或替代；
- 可拔插的粒度是**团队**：每团队一份装配资产，团队内层/角色/技能/flows 可以完全不同，但**门禁与状态机是同一套**。当前内置四套：`software-team`（软件工程）、`design-team`（ComfyUI 媒体与平面）、`research-team`（调研）、`writing-team`（写作）。

## 二、设计理念与落点

核心命题：**`plan-exec-audit` 能覆盖大部分专业乃至通用任务**；把单 Agent 的「思考-执行-自检」**外延为多 Agent 执行规范**，以**拆分单 Agent 上下文**、**阻断「自主判断 → 需求漂移」**，并把执行规范**落地到门禁与状态机**，替代单 Agent 自主执行。

| 理念 | 引擎里的实现 |
|---|---|
| plan-exec-audit 分层 | 批次按 plan（规格/拆解）→ exec（实现/验证）→ audit（验收对账）三层；**audit 是一等公民**——批次 `complete` 前必须有 audit 结论 |
| 自检外延为执行规范 | 单 Agent 自检拆为**角色 + 契约**：exec 产证据、audit 独立复核（换路径反向抽查）、Leader 只做终门禁综合（消重、标冲突、核证据，**不拼接成员输出**） |
| 拆分单 Agent 上下文 | 每个 lane = 一个短生命周期 worker，任务包只含「角色 / 目标 / 关键契约 / 验收标准 / 产物契约」；跨轮信息只走 mailbox 元数据与产物文件，不依赖上下文继承 |
| 阻断需求漂移 | 需求在 plan 层冻结为**规格 + 任务树**（spec 必含裸标题 `## 验收标准`、`## 约束`）；exec 入口由 `consume` 门禁把关（缺上游产物**拒派**）、出口由 `outputs` / `produce` 把关（缺产物**拒 merged**）；判据之外的主张只能进 gap-list，不得改口径 |
| 门禁与状态机替代自主执行 | 三层门禁 + 状态机（批次 5 态 / 成员 8 态）+ 事件流（可审计）；**失败 lane 为终态**（重做 = 重开新批次）；门禁由引擎强制，不依赖自觉 |
| 难度路由 | A/B/C 三档：单线程直做 / 单 subagent / 集群建批（**无默认档**——由 Leader 用 `assign_check({ difficulty, rationale, scope: "full" })` 主动写入难度与判据；**三层批**建批须传 `assembly`（`auditLane` 必填；`managerPlan` 缺省 `raise`））。**单线程任务一律不建批**；升 C 的判据是「明确多线并行或多依赖」，不是调用次数。**档位 × 工具面（G1）**：`wave_plan` / `member_status` / `member_settle` 要求**调用方会话**已写入 C（未评估 / A / B 拒 `GATE_BATCH_REQUIRES_C` / `GATE_MEMBER_REQUIRES_C`；**判据落调用方**——建批只认本会话 C，成员状态仅「本会话 C」或「该批已登记 Manager 会话」，**已取消父档继承**）。**建批即拉起（G2）**：声明 `raise` 的批未登记 `batch.manager` 时 **exec 层 lane 派发即拒** `GATE_MANAGER_NOT_RAISED`（plan 层不受限；lane 为 `idle`（**空闲态**——非崩溃态，返工/续跑可调用）时按 G-1 降级放行） |

## 三、可拔插内容**引擎资产化**

- **唯一权威来源**：`presets/<team>/team-asset.yml`（层 × 角色 × 技能 × flows × 状态机覆盖）。**未声明处回落引擎基线**（tighten-only 唯一真源；**legacy 回落层已完全清退**——旧批不追溯、代码内无兼容分支）；状态机**只许收紧**，永不静默放宽；
- **引擎化程度**：读端与校验器是引擎代码；资产随包分发并做**加载期校验**——非法声明**拒载**（不是"忽略"）；团队角色**声明面即白名单**（`layers[*].roles` ∪ `roles.extra`，与引擎基础集并集），牵头角色须另用 `plan_leads` / `audit_leads` 显式声明；资产改动以「路径 + mtime + size」签名判新旧，**改后即时生效**（免重启）；
- **临时团队**：无预置团队时，可写会话级临时团队资产并以 `wave_plan({ team, teamsRoot })` 建批——**装配面与 flows 面同引擎语义**（同一校验器、同一门禁），团队不必"内置"；
- **技能与资产的边界（纪律）**：**技能只写用途与指针，装配数据只写资产**。技能承载装配数据会落后于资产（会致 worker 静默少手册），因此引擎在建批期校验技能可解析性并给 `GATE_SKILL_MISSING` 告警。

> **技能名口径**：装配内一律写**加载名**（宿主技能 `SKILL.md` 的 frontmatter `name`），宿主**目录名可以不同**；可解析性判定取「目录名 ∪ 加载名」。

## 三·补 设计要点（机制清单：每条都应能在代码里找到读端）

| # | 要点 | 一句话判据 | 落地 |
|---|---|---|---|
| 1 | **契约先行** | 产物路径与章节在 plan 层冻结；exec 缺上游产物**拒派**（entry 门）、缺产物**拒 merged**（exit 门） | `consume` / `produce` / `outputs` + plan 契约（裸标题 `## 验收标准`、`## 约束`） |
| 2 | **状态机单一事实源** | 批次 5 态 / 成员 8 态的迁移只认状态文件 + 事件流；**`idle` = 空闲态（非崩溃态）**，`idle→running` 是返工/续跑入口 | `lib/state/store.js` + `machine-rules`（棘轮：只许收紧） |
| 3 | **门禁不靠自觉** | 入口/出口/完成三类门由引擎强制；命令 gate 在 merged 前**实际执行**并以退出码判定 | `lib/state/gates.*`；`gate:` 行须 cwd 无关 |
| 4 | **可审计留痕** | 每次判定/降级/逃生都产事件（`gate.*` / `member.*` / `batch.*`）；**拒载侧与放行侧留痕口径不同**（B2 首触只在放行/降级侧发射），不得混谈 | `lib/state/event-types.js` |
| 5 | **装配资产化** | 层/角色/技能/flows 全在资产；**技能只写指针，不写装配数据** | `presets/<team>/team-asset.yml` |
| 6 | **难度路由（无默认档）** | Leader 主动写入 A/B/C + 判据；**单线程不建批**；G1 档位×工具面；G2 建批即拉起 Manager | `assign_check` / `wave_plan({assembly})` |

| 8 | **契约缺声明可见** | 团队未声明某检查项而引擎缺省接管时**首触留痕**（`gate.contract_missing`），判定不变 | 同 #4 |
| 9 | **宿主级自验证** | 完成判据含真实宿主加载/启动冒烟；语法/单测只是中间 checkpoint | 纪律 §10 |

## 三·补2 反冗余红线（产品级审查判据，违反即技术债）

1. **要么接线，要么标废**：声明/字段/事件不得「写了不生效」；未接线声明须在台账显式标注（`UNWIRED_DECLARATIONS`）或标废（如 `TEAM_ASSET_CONTRACT_LEGACY`）。
2. **禁双真源**：同一语义只留一个真源——audit 内容契约 = `audit_contract`（旧泛键 `contract` 已标废）；完成白名单 = `audit_contract.verdict`。
3. **禁预留想象物**：「无写端无读端」的事件/字段/码不得保留；**标废前必须先证伪「已有消费点」**（本轮实测：`gate.target_blocked`/`gate.target.passed` 原本被判「预留」，实有写端与读端 ⇒ 裁决推翻）。
4. **门禁语义只许收紧**：新码要么拒载/加门，要么纯留痕；不得以「兼容」为名放宽既有判定。
5. **文档-实现同源**：纪律/介绍里的每条「已生效」主张须能在代码里找到读端；找不到即漂移（本文件自身受此约束）。
6. **测试退化必须机器取证**：**断言调用数下降即红；等价替换不在覆盖内**（B5 已加恒真形态启发式，见下）。删断言/删用例不得「静默 0」。
   - **机制口径（防过度承诺）**：基线快照计的是 `assert.<方法>(` **调用点**（`scripts/baseline-snapshot-core.mjs:195`），故 `assert.equal(x,期望)` → `assert.ok(true)` 这类**等价替换不产生调用数漂移**，不在该机制覆盖面内 ⇒ 由**恒真形态启发式**兜（`assert.ok(true)` / `assert.ok(1)` / `assert.equal(x,x)` 同构，命中即判退化；本批 B5 落地，未落地前不得声称已覆盖）。

> **红线靶子（用户口径，2026-09-15）**：本节的靶子是**引擎内部运行状态与技术资产不得冗余**——**同值双字段** / **双路径台账** / **双份实现** / **双真源** / **零消费者资产**；判定统一按 #1「要么接线，要么标废」与 #2「禁双真源」。

## 四、二次开发与接口化（当前立场）

- 可拔插内容的二次开发**仍高度依赖引擎基础设施**，作者面目前以引擎侧为主；
- **接口化：暂搁置**。对外语义当前是「治理工具面 + 资产格式」，二者都在**门禁之内**；任何跨进程/跨平台的互联层都不携带执行门禁——按它分发拔插内容，会让**执行规范在边界处脱落**；
- 立场：**门禁 > 互通**。若将来做接口化，前置条件是"**门禁可作为协议的一部分被传递与强制**"（等价于把入口/出口/契约/完成判据一并外化）；否则只做**只读**的资产读取接口。

## 五、与早期设计表述的差异（诚实清单）

1. **"软件工程专用"已不成立**：引擎语义本身是专业交付通用，四套团队中三套非软件；
2. **"团队"不再等于"内置"**：临时团队让未预置的团队也走同一门禁；
3. **纪律与细则分层**：persona 只保留「每轮必看的判据 + 指针」，码表与操作序列在 `presets/punky-preset/references/discipline.md`——目的是防"指引与实现漂移"；
4. **管理角色定位**：Manager 是**引擎层功能角色**（不属任何层、不占 lane、只代劳指挥）；**派发与结算写入默认归 Leader**；
5. **可验证性前置**：宿主级加载/启动冒烟与"消费方契约摸底"属完成判据；「未接线声明」不得写入资产或指引。
6. **`.ts` 与纯 JS 源并存**（2026-09-15 实测订正）：`lib/**` 中**部分**文件是 TS 源（有同名 `.ts`，如 `lib/state/gates.ts`），其 `.js` 是 `npm run build` 的产物；**其余是纯 JS 源**（无同名 `.ts`，如 `lib/assembly/team-asset.js`、`lib/state/store.js`），直接改动即生效。任何「引擎源码全是 `.ts`」的表述都是错的。
7. **i18n 缺口**：本文件（`engine-intro.md`）暂无 `.en` 对照，其余 `docs/**` 多为双语——待补或明示「仅中文」。
