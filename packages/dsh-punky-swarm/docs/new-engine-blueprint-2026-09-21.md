## 2. ★ 红线重述：从「禁重算」到「**层内可重算**」

### 2.1 原红线（2026-09-21 前）

> **禁隐式/无痕重算；允许显式留痕的图修订**（显式调用 + 单次原子写 + `reason/author/revision` + 落 `events[]` + 变更后重跑全部建批期校验）；H1「建批后绝不重算 DAG」。

### 2.2 新红线（本裁定放宽后）

- **层内可重算**：同一 layer 内，任务集合可**增 / 删 / 拆细 / 合并 / 改派 / 改依赖**。前置条件（三条同时成立）：
  1. 目标 lane **未启动**（`status === 'pending'`）；
  2. 其产物**未被任何下游 consume**（`downstreamConsumed(lane) === false`，判据 = `batch.handoffs` 对应边未被读）；
  3. 走**显式修订调用**，沿用原红线的四件套（单次原子写 + `reason/author/revision` + 落 `events[]` + 变更后重跑**该层**全部建批期校验）。
- **跨层仍禁**：一旦某 lane 产物被下游 consume，该产物**及其上游依赖链**冻结 ⇒ 改动只能走**追加新 lane**（R4-1 形态，新 lane `deps` 指旧 lane 产物 + `reason` 引 gap-list），不是改旧 lane。
- **机读判据**（待落闸）：`lane.status === 'pending' ∧ downstreamConsumed(lane) === false`。
- **未放松的部分**：「禁**隐式**重算」一字未松——放宽的是**范围**（批级 → 层内），不是**留痕要求**。

### 2.3 与 jiuwen 的边界（受限采纳）

| jiuwen 形态 | 原判 | 本形态下 |
|---|---|---|
| **原子图变更 + 后置再校验 + 环检测在变更后图** | 可借（M-1） | **采纳**（`task_manager.py:174 add_graph` / `:487 mutate_dependency_graph`） |
| **变更结果对象** `TaskOpResult{ok,reason,data,refreshed_tasks}` / `GraphMutationResult` | 可借（M-2 / OJ-6） | **采纳** ⇒ C1 里 6 个安全守卫的解冻正门（§6） |
| **在办任务原地改内容 + 通知重读**（M-4） | 冲突 | **不取**（撞「产物已被 consume 即冻结」） |
| `task_id:"*"` 全取消 / 改派在办任务 / 取消成员（J1 运行期改图） | 冲突 | **不取** |
| 返工回路 `in_review → in_progress`（J2） | 冲突 | **不取**（撞失败终态） |
| SQLite DAO + `team.db`（J1/J9） | 冲突（撞 H3） | **不取** |
| 内容寻址 journal `sig=SHA-256(prompt+opts+schema)` | 可借 | **借作「任务指纹」** ⇒ 判「任务是否被隐式改过」+ 重复派发/重复结算的幂等判据（§5.3） |

## 4. 目标一：更细地拆分任务

- **现状粒度**：lane ≈ 任务，粒度被「层」这个粗粒度桶夹住（三层批 plan/exec/audit 各一桶）。
- **新粒度**：**任务是图、层是闸** —— 层仍承担闸语义（层间有闸、层语义为主），但层内任务数不再受 lane 数约束。
- **拆细落点**：`task.deps`（DAG 边）+ `task.owner` 可选（未指派入公共池等认领，借 jiuwen J1「未指派入公共看板等认领」）。
- **防碎判据（须你裁，§8-3）**：建议「最小任务 = **一个可验收产物**」；`task_split` 必须**继承父任务的验收标准**，否则拒（防把一条任务拆成十条无验收碎片）。
- **并发上限不因此上升**：拆细是**图粒度**，不是同时在跑数（见 §5.1 的 WIP 判据）。

## 5. 目标二：更稳定的高并发

### 5.1 WIP 判据（与 jiuwen 的关键差异）

jiuwen J1 是「**每成员同时只能有 1 个 `in_progress`（WIP=1）**」。蟛蜞的 lane 是**短生命周期 worker**，并发 = **多 lane 并行**而非单成员多任务 ⇒ **WIP=1 天然成立，无需搬**（搬了反而是新约束）。

### 5.2 稳定性四条

1. **单写者 + 原子写**（`store.js` 既有）：黑板任何变更 = 一次 `atomicWrite`，全成或全败。
2. **槽位与准入口径归一**：Q-B 取消并发闸后，`batch.concurrency` 只作声明/回显、`maxMembers` 是唯一槽位概念 ⇒ 新形态须**实证官方槽位真拦**（路线稿 O-10，**未取证**）。
3. **幂等 / 重放安全**：用任务指纹 `sig` 判「重复派发」「重复结算」（借 jiuwen 内容寻址，§2.3）。
4. **变更返回结果对象**：`assertMemberTransition` / `assertBatchTransition` 由裸 throw 改为 `{ok, reason, data, refreshed}`（M-2 / OJ-6）⇒ 与 C1 解冻同一动作（§6）。

### 5.3 已知短板（J4 对位，非本形态必解）

jiuwen 有 6 类探测器 + 4 档 severity + 分级处置 + 强度预算；蟛蜞 `lib/watch/lane-heartbeat.js` 只有「停滞」一维 ⇒ **高并发下「跑飞/反复重试」类故障无分级处置**。建议列 N3 波（§7），**不阻塞** N1/N2。
