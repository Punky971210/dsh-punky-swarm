# 调用链矩阵模板

> 本文档定义前端行为触发的完整调用链映射，作为 spec.md 的组成部分。
> Designer 在产出四件套时，必须为每个涉及前端-后端交互的行为填充此模板。
> **目标**：确保每个前端变更的调用链完整性，避免"修改项独立作用"和"孤儿代码"。

---

## 调用链总览

| 调用链 ID | 触发端 | 起始事件 | 中间链路 | 终结点 | 穿透层级 | 复杂度 |
|-----------|--------|---------|---------|--------|---------|:------:|
| CH-01 | 前端 | PageX.submitBtn.onClick | → API /api/v1/xxx → ServiceX.method() → Repository.find() | DB table_x | 4 层 | 中 |
| CH-02 | 前端 | PageY.searchInput.onChange | → API /api/v1/yyy → ServiceY.search() → External API /ext/zzz | 外部服务 | 4 层 | 高 |

### 穿透层级说明

| 层级 | 含义 | 示例 |
|:----:|------|------|
| 1 | 前端事件层 | 用户操作、组件生命周期、路由变更 |
| 2 | 前端数据层 | API 调用、状态管理(Store/State)、本地缓存 |
| 3 | 后端 API 层 | 路由、中间件、请求/响应处理 |
| 4 | 后端服务层 | 业务逻辑、服务编排、数据组装 |
| 5 | 数据层 | 数据库读写、外部服务调用、缓存读写 |

## 逐条调用链详述

### CH-XX：{行为描述}

#### 完整链路

```
前端事件层:
  [PageX.Component.Event] → 事件 handler 执行
     ↓
前端数据层:
  状态变更 (loading=true) → 构建 API 请求参数 → 发起 HTTP 请求
     ↓ HTTP Request
后端 API 层:
  路由匹配 → 中间件(鉴权/参数校验) → Controller 处理
     ↓
后端服务层:
  Service 方法调用 → 业务规则执行 → 数据组装
     ↓
数据层:
  Repository/DAO 查询/写入 → DB / 外部服务
     ↑
后端服务层:
  结果处理 → 异常转换 → 响应组装
     ↑ HTTP Response
前端数据层:
  响应解析 → 状态更新 (loading=false) → 数据绑定 → UI 渲染
```

#### 关键节点

| 节点 | 角色 | 预期行为 | 异常处理 |
|------|------|---------|---------|
| **事件触发** | 前端 | 用户操作后触发事件 handler | 防抖/节流/重复提交防护 |
| **API 调用** | 前端 | 构建请求参数，发起 HTTP 请求 | 超时重试、网络不可达提示 |
| **权限校验** | 后端 API | 验证用户身份和权限 | 401 跳转登录 / 403 无权限提示 |
| **业务处理** | 后端服务 | 执行业务规则，组装结果 | 业务异常 → 结构化错误码返回 |
| **数据访问** | 数据层 | 查询/写入数据源 | 连接超时/数据不存在 → 降级或报错 |
| **状态更新** | 前端 | 解析响应，更新本地状态 | 响应异常 → 错误 UI 展示 |
| **UI 渲染** | 前端 | 根据最新状态重新渲染 | 渲染异常 → fallback UI |

#### 影响面分析

| 影响组件 | 影响类型 | 影响描述 | 防范措施 |
|---------|---------|---------|---------|
| `{ComponentA}` | 直接 | 调用链变更导致其输入数据格式变化 | 同步更新组件接口适配 |
| `{ComponentB}` | 间接 | 依赖同一 API 的不同调用链可能受影响 | 回归测试该组件的调用链 |
| `{API Name}` | 直接 | 修改 API 响应结构可能影响其他前端页面 | 新增字段而非修改/删除已有字段 |

#### 调用链验收标准

```
[CH-XX] 调用链验收标准
- [ ] 完整调用链可通过端到端测试验证
- [ ] 每个节点的输入/输出可独立断言
- [ ] 任一节点异常时，调用链有明确的降级/错误处理路径
- [ ] 影响面中的全部组件完成回归测试
- [ ] 无孤儿代码：调用链中所有修改点都有对应的消费者
```

## 孤儿代码防范检查

### 修改项影响面声明

| 修改项 | 类型 | 影响范围 | 反向依赖 | 风险等级 |
|--------|------|---------|---------|:--------:|
| `{文件名/组件}` | 新增/修改/删除 | {影响的调用链 ID 列表} | {依赖该修改项的其他模块} | L/M/H |

### 检查规则

1. **每项修改必须标注影响面**：修改什么 + 会影响到哪些调用链 + 哪些组件会受影响
2. **每项删除必须确认反向依赖**：删除前 grep 全项目确认无其他消费者
3. **每项 API 变更必须兼容**：新增字段/可选参数优先，禁止直接修改或删除已有字段
4. **调用链断裂检测**：如果 A 调用链的产出是 B 调用链的输入，修改 A 时必须同步验证 B

### 风险等级定义

| 等级 | 含义 | 处理要求 |
|:----:|------|---------|
| **L** | 影响面可控，仅涉及单个组件/文件 | 常规自检即可 |
| **M** | 影响多个组件或调用链 | 回归测试受影响范围 |
| **H** | 影响面跨模块/跨团队，或存在断裂风险 | **回报人审，给出影响分析报告和建议方案** |

## 调用链复杂度与人审门禁

| 复杂度 | 判定标准 | 处理方式 |
|:------:|---------|---------|
| **低** | 2-3 层，无外部依赖 | Reviewer 常规审查 |
| **中** | 3-4 层，有外部依赖但有明确降级方案 | Reviewer 常规审查 + Supervisor gap-list 对账 |
| **高** | ≥4 层，多个外部依赖，或存在数据一致性风险 | **Supervisor 回报人审，给出影响分析和建议方案后由用户决策** |
