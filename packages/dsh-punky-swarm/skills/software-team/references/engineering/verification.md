# 检查与验证

> **适用角色**：tester（执行与读数）· reviewer（审查与复跑）· supervisor（验收证据口径）· coder（最小自检读数）。
> **定位**：管「验证怎么才算数」，与 SKILL.md 的 `gate: <命令>` 门禁（`workflow.md` §四 dp2）配套使用。

---

## V-1 能机器判的规则必须落成检查

写进文档但没人执行的「规则」不算治理。凡是**能机器判定**的项，必须落成一条可执行命令：

- 类型 / 接口契约；
- 依赖方向（如反向 import）；
- 未定义的样式 token / 组件类型；
- 原生危险调用（如原生 confirm / alert 绕过统一浮层）。

**可核判据**：每条硬规则在产物里能指到**一条可执行命令**（并可按 `gate: <命令>` 形式进门禁）。

---

## V-2 检查范围必须逐项说明

**命令名相同 ≠ 检查范围相同。** 每次交付必须写清三件事：

1. 这条检查**覆盖哪些项**（逐项列，不写「已检查」）；
2. **退出状态**是什么（exit code）；
3. **失败是否真的阻断**后续流程。

**反例**：日志里打印了错误但构建继续跑完 ⇒ **不算阻断**。

---

## V-3 入口一致性

本地命令 / 提交钩子 / CI / 发布入口是否执行**同一套**检查，逐入口说明「有 / 无」。

- 缺失的入口 = **可绕过面**，必须在 gap 清单里点名；
- 只在一个入口检查，却在报告里写「已做检查」= 口径失真。

---

## V-4 检查类型不可互相替代

| 不能替代的关系 | 说明 |
|---|---|
| 类型检查 ≠ 行为测试 | 类型对不代表按钮不会重复提交 |
| 构建成功 ≠ 交互正确 | 构建证明能打包，不证明状态正确 |
| 前端通过 ≠ 后端通过 | 两套检查覆盖面不同，必须分列 |

不同检查的覆盖率必须在报告里**分列**，不得合并成「全部通过」。

---

## V-5 交付四态

每条验证项必须标四态之一，并给计数：

```
通过 N / 失败 N / 跳过 N / 未验证 N
```

- **跳过**必须给原因（环境缺失、平台不符、范围外）；
- **未验证**必须给原因与风险（缺依赖、未接入、时间不足）；
- **禁**写「全绿 / 全部通过 / 总体没问题」这类**无计数**表述。

---

## V-6 结论锚定代码状态

- 每份验证结论必须绑定**对应代码状态**：`commit sha` 或工作树快照（未提交时给出明确标识）；
- **历史通过记录不得替代本次检查** —— 代码变了，旧读数即失效；
- 跨轮验收时，「上次是绿的」**不是**证据。

---

## V-7 证据形态

- 命令**原文** + **原始输出**（不转述、不美化、不截断关键行）；
- **未验证就写「未验证」**；
- **不得**把「测试建议 / 应该能过」写成「测试结果」；
- 报告里区分三类：**实际执行过的** / **只做了静态检查的** / **没做的**。
