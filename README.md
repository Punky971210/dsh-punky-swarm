> **一个 Agent 好管，一支 Agent 队伍难管。**
>
> 蟛蜞工程引擎把「谁该干活、干到什么程度算交付」从人的注意力里搬进引擎。任务按难度分级，批次按时序编排，交付按门禁验收，越界按调用裁决。你只做两件事：说清要什么，验收做出来什么。

## 从「人在流程里当瓶颈」说起

一个人跑单 Agent 全流程，往往跑成了人工辅助自动化：设计、编码、测试、审查都塞给同一个 Agent，它干一件，你看一眼，点个头，它再干下一件。人卡在自动化的节点之间，成了整条链上最慢的一环。

那就上编排框架。可流程图一画，节点写死、边写死，需求一变就得重画；Agent 想绕个更省的路，图里没有那条边。Agent 的自由度被压到最低，改动成本高到只能另开一条流程。

两头都不讨好。蟛蜞工程引擎取的是中间那条路：**流程不写死，但交付不靠自觉。** 引擎不规定 Agent 怎么做，只在关键节点上问一句——该交的东西交了没有，该验收的验收了没有，这一次调用越没越界。答不上来，就停在这一步。

## 三件套：引擎给能力，模式规范行为，指引教你怎么用

| 件 | 是什么 | 缺了会怎样 |
|---|---|---|
| **引擎** | 一个 dsh 插件，提供治理能力：任务分级、批次编排、门禁、单写者锁、存档点、调用级护栏、只读监控面板 | 模式和指引变成空谈 |
| **模式** | 一套预设：角色设定、治理纪律、启动引导、行为规范，告诉 Agent 在这个集群里该怎么做事 | 引擎退化成一堆没人用的工具 |
| **指引** | 一套团队技能：分层角色手册、产物格式、模板，教每类角色加载什么、产出什么 | 每个 Agent 都按自己的理解干，交付形态不可预期 |

三件套都随包安装，装完即是可运行的团队，不需要你再搭一套。

## 四道闸口：把「人盯流程」换成「引擎盯流程」

以前是人坐在屏幕前，一个环节一个环节看跑完没有。现在换引擎来看。

- **派发前**：下游要用的上游产物没交齐，下游不许开工。
- **合并前**：计划类产物要做结构校验，该有的章节缺一段就退回。
- **结算前**：声明要交的产物没落盘，不许结算。
- **收尾前**：验收没完成、有失败或冲突的批次，不许收口。

四道闸只做一件事：**不合规就卡住，合规就放行。** 半成品不会自己走到你手里。

## 难度门禁：先判这一趟该谁干

每轮动手之前，先给任务定级：

- **A 级**——顺手的小活，直接干；
- **B 级**：需要独立上下文或工具面，交一个 Subagent；
- **C 级**：多环节、要并行、要验收、要可恢复，走整条批次流水线。

**拿不准就判 C。** 判了 C 却没建批就动手，引擎直接拒绝；评估会过期，防止一路闷头干下去；前面手工摸底产出的东西可以归位复用，不白干。

这一层的意思很直白：**让引擎强制做规划，而不是靠自觉。** 简单任务不必背团队级开销，复杂任务也不会把 Agent 的上下文撑爆。

## 批次一旦建立，结构就不再变

批次按依赖关系分层成波次。波次之间可以声明依赖，谁等谁、谁能并行，建批那一刻就定死，中途绝不重算。

固定比动态好在三处：可追溯——任何时候回头看，都能知道这批任务最初长什么样；可审计——每个任务在哪一波、谁做的、什么状态，一目了然；可复现——同样的输入，同样的编排，同样的执行路径。

任务可以声明自己属于计划层、执行层还是审计层，也可以声明取用谁的产物、自己交什么、由谁来做。同层可以并行，跨层有门禁。

## 一笔一笔记账，一件一件留痕

- **状态文件是唯一事实源**：批次和成员的状态以状态文件为准，不靠口头汇报推断。
- **事件流全程留痕**：批次推进、交接、结算、门禁判定都落事件，可回放。
- **单写者锁**：同一份活同时只有一个写者，冲突保留现场交人裁决，不静默覆盖。
- **存档点**：每完成一个子步骤就保全一次，崩溃后可查、可续，中断只是停在存档点。
- **只读监控面板**：装在 Web UI 里，批次列表、统计、lane 状态、事件时间线与收件箱计数一眼看全。引擎只做裁决不做修改，人工只能查看。

## 每一次工具调用也能被裁决

除了批次门禁，调用级护栏逐次判定工具调用，六种裁决原语覆盖放行、拒绝、转人工审批、收窄参数、延后与暂停。命中即产出**可验篡改的拒绝收据**（按哈希链锚定，改一个字节即断链），Agent 收到的是「被哪条规则拦下」，不是一句泛化的「请求被拒绝」。

护栏出厂规则为空，装上不改变既有行为；规则按需启用、先审后用。

## 装进来你会得到什么

- **治理面**：三层门禁、批次 5 态与成员 8 态状态机、单写者锁、隔离工作区与存档点、任务难度门禁、产物归位。
- **协作面**：显式消息通道（三个信箱，只写元数据、消费需确认）、心跳与长跑探针、批次事件结局分型。
- **调用面**：六原语护栏、拒绝收据与哈希链、规则预设（敏感数据防护 / 资源边界 / 两者合并）。
- **可观测面**：只读监控面板、进程级本地审计日志（默认开启、不外发）。
- **团队技能（5 套）**：`software-team`、`design-team`、`research-team`、`video-team`、`writing-team`。软件工程那套另含规格语言原文与适配层——写规格、查结构、验一致性都有据可依。

## 为什么是层级拓扑

| 形态 | 好处 | 代价 |
|---|---|---|
| 星型（中央集权） | 简单直接 | 中央一崩全崩；上下文窗口有限，管不了太复杂的集群 |
| 去中心化（人人协商） | 无单点故障 | 协调成本指数上升，状态不可追溯 |
| **层级（蟛蜞模式）** | 同层并行、跨层门禁；按认知负载分层，各司其职 | 需要一套纪律，但纪律可以写在引擎里 |

一句话：**保障稳定，而非限制自由。** 工具层全量开放，模式层只给指引，团队装配可插拔，你想换哪套角色体系都行。

## 它管不到的地方

这一段比能力清单更重要。

引擎不判模型意图——护栏工作在工具调用层，模型自身的生成与推理不在防线内。不做沙箱，不做联网准入网关，不检测绕过显式通道的侧信道。不提供一次性写入存储，哈希链防的是静默篡改而不是删除，也没有第三方权威签名。判定不了调用者身份，留痕起记录与可见性作用，不构成访问控制。单机进程内治理，不做跨机编排。护栏出厂规则为空，裁决恒放行，配好规则才真正拦得住。

所以它不会替任何人宣称「防住了模型跑偏」。它提供的是一种位置选择：**把可判定的越界与交付缺失，拦在执行期，而不是等它变成一份事后报告。**

## 谁该用它

一个人或小团队，做的是**有验收标准的交付**——代码、调研、设计、写作都算。需要产物链可审计、失败可追溯、越界可拦截，还希望数据留在本地。

不适合只想「一句话让 AI 把活干了」的场景。这套机制的开销全花在验收标准上，没有验收标准的活，用不上它。

## 安装

前置：已安装 DeepSeek Harness（dsh），Node.js ≥ 22。

```sh
# 安装并装入 dsh（profile 按实际使用的替换）
dsh plugin add dsh-punky-swarm
dsh web restart
```

> 备选：`npm install -g dsh-punky-swarm` 后以 `dsh plugin --profile <profile> add dsh-punky-swarm` 装入；开发路线可用 `link:` 指向本地包目录。

装好后重启 dsh，会话区多出蟛蜞集群面板，团队技能自动同步到你的用户目录——**安装即得，无需额外配置**。
